# 复杂度：为什么"快"要先问规模

周六下午，你把手机里的通话记录导成一张表，想找出去年三月给装修师傅打过的那通电话。手指停在屏幕上，第一反应是"这有什么难的"。

难不难取决于两件事：用什么找法，以及这张表将来会长到多大。这一页只回答一个问题：为什么"能算出来"和"算得完"是两件事。答案不在机器好坏里，在"规模翻上去以后谁先撑不住"里。

## 大 O 不比谁快，比的是增长形状

CLRS 第 3 版第 3 章把记号定义得很干净：O(g(n)) 是一族上界，Ω 是下界，Θ 是两者的交集，形式定义里还带着一个正常数 c 和一个起点 n₀。由此能直接推出那句常被说反的话：**"大 O 就是最坏情况"是双重误用**——大 O 只谈函数怎么涨，最好、最坏、平均说的是"哪种情况"。一句合格的话长这样："插入排序的最坏时间复杂度是 O(n²)"。

上面这一左一右就是全页的地基：大 O 只描述增长率，不含常数、不含硬件、不含数据分布。所以"O(n log n) 比 O(n²) 快"这句，印出来前必须先补一句"n 足够大"。记号也不是某一年凭空出现的：Landau 等一批数学人在 19 世纪末 20 世纪初用起了 O，Knuth 1976 年的论文才建议把 Ω 与 Θ 正式纳入体系——"Knuth 发明了大 O"同样是错的，他推广的是整套记号族。

## 十亿条数据，两种找法差七个数量级

先把两个词说人话。**线性扫描**：一格一格看过去，看到算完。**二分查找**：每眼先看中间，砍掉一半，再看剩下那半的中间——前提是这个列表已经排好序。

有序的情况下，在十亿（10⁹）个元素里做二分查找，最坏比较次数是 30 次，因为 log₂(10⁹) 等于 29.897，向上取整就是 30。无序的数组平均要检查约一半元素，十亿条就是约 5 亿次。

  <div class="mp-stat"><strong>30 次</strong><span>十亿个有序元素里二分查找的最坏值</span></div>
  <div class="mp-stat"><strong>约 5 亿次</strong><span>无序时线性扫描平均要看的条目数</span></div>
  <div class="mp-stat"><strong>约 7 个数量级</strong><span>两者相除的量级差，只在全在内存时成立</span></div>

上面这三个数连起来读是一句话：同一批十亿条数据，找法不同，工作量差约 7 个数量级。限定语得跟着：**30 是"比较次数"，不是"时间"**，这七个数量级也只在全在内存、每次随机访问代价相同的前提下成立。这 30 次里只要有一次落在磁盘上或跨一次网络，那一段就由读写决定，跟比较次数无关；而线性扫描对缓存友好，小规模数据上反而先跑完。

这就是"能算出来"和"算得完"的分界线：前者问有没有步骤，后者问步骤数配不配得上你的耐心。

## 一百万个元素两两比较，和一百个是两种命运

对 n 个元素做"两两比较"，次数是 n(n−1)/2。把 n 换成 100 万，这个数约是 5×10¹¹ 次；同一批数据按 n·log₂n 记账只有约 2×10⁷ 次，相差约 4 个数量级——这也顺手回答了"为什么排序不是把所有顺序都试一遍"。限定立刻要跟上：**这只是次数，不是时间**，常数、缓存、输入输出都还没进去。

## O(1) 听着最爽，它可能反而最慢

"O(1)"的字面意思是操作次数不随规模增长，听起来像免费。可渐近记号把常数项和低阶项全丢掉了：一个需要 10⁶ 次基本操作才完成的 O(1)，比只要 10 次的 O(log n) 更慢；内存布局和哈希冲突也常常被它忽略。

术语当场解释：**哈希表**就是"按名字算出一个号码，直接去那个柜子取"的寄存处；两个名字撞出同一个号码（也就是冲突）时，就得在同一个柜子里翻，那"一步到位"就退化了。说穿了：大 O 是趋势，不是速度表；那一口价是 3 次还是 10⁶ 次，记号里没提。

## 同一套步骤，换份数据就差一个数量级

复杂度不是唯一的决策因素：同一个算法换一份数据分布，差一个数量级是常态。快排在近乎有序的数据上会退化，插入排序在这种场合反而是最佳选择；归并则要额外 O(n) 的存放空间。所以"哪个算法更好"的正确回答是"**在什么数据上**"。真实库里子数组短到一定程度就切回插入排序，各家门槛都是调参结果，没有普适阈值。拿大 O 当排行榜，是这一页最想拦住的用法。

## 印复杂度时，必须一起说"拿什么实现"

同一个算法、换一种数据结构，界会变：Dijkstra 的原始版本是 O(n²)，用二叉堆可到 O(m log n)，用 Fredman 与 Tarjan 1984 年的斐波那契堆理论上可到 O(m + n log n)；教科书常写的 O((m+n) log n) 是优先队列那一套记账方式。大 O 本身不含常数，单独印一个阶，等于只报了半件事。
