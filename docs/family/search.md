# 查找与排序：先找到，再排好

周三夜里十点半，你在两千多行的报销表里找一笔三月的停车费。按下查找键，敲进金额，回车——两秒，光标跳到了那一行。

这两秒里机器只可能走了三条路：一格一格数；每次翻开中间那格、扔掉一半；或者根本不翻，直接报出它住哪一格。这页只回答一个问题：三招各要付出什么，各又偷偷要求你先做什么。

## 从头翻看着笨，但它什么都不要求

一格一格数（学名叫线性查找）是唯一对"这堆东西压根没排过序"依然成立的办法。折半的前提得摆在最前面：数据已经排好，而且能直接跳到任意一格。名单没排序时，砍中间那一下毫无意义——你要找的那条完全可能在被扔掉的那一半里。

## 折半省下的是查找，排序这笔账要另算

想把二十万条记录排好再折半，你得先付排序这笔钱。更微妙的是：教科书判插入排序 O(n²)，真实标准库却偏偏拿它收尾。

上面这张图横轴是子区间长度 n（1 到 64），纵轴是运算次数，每上一格就是 10 倍。按公式算到 n = 64：完全乱序的插入排序要挪 n(n−1)/2 = 2016 次，参照线 n·log₂n 是 384 次，而同一个插入排序在近乎有序的数据上移动次数约等于 n、也就是 64 次。逐点比还有两个交叉点（次数全按公式算、不是实测）：完全乱序那条从 n = 7 起超过参照线（21 次对 19.6 次），近乎有序那条从 n = 3 起就一直压在下面。图旁"多小算小"的口径一起读：GCC 的 libstdc++ 在子区间不超过 16 个元素时停止递归、最后统一用插入排序收尾（源码常量 _S_threshold = 16），CPython 构造有序段的上限是 64；有中文资料转述某个 C++ 标准库用 30，本轮没查到一手，图上标了"待核"，正文也不当结论。这些数全是实现调参的结果、不是理论常数，所以这页不印"多少个以下必然更快"那种通用阈值。

## 稳定不是随机，是"相等的那些不许换位置"

稳定性只承诺一件事：金额相等的两行，排完之后保持原来的先后。C++ 里 std::sort 不保证稳定、std::stable_sort 才保证（通常是归并，额外空间可能到 O(n)）。"不稳定等于结果随机"是误读——同一输入同一实现，不稳定的结果照样确定，只是不担保相等元素谁在前。归并最坏和平均都是 O(n log n)，代价是要 O(n) 临时空间；快排原地干活、期望栈只有 O(log n)，但不稳定。这页不给"谁更好"的排名。

## 直接报号码那一招，靠的是一个寄存处

哈希表：把东西按"名字算出来的号码"放进柜子的寄存处。要找它，先重算一遍号码，直接走到那一格。

它确实快，可那句 O(1) 后面跟着一串前提。按 Java 的 HashMap 文档口径：默认负载因子 0.75，装载超过门槛就把表扩成 2 倍；某个桶上的链表长度达到 8 且表容量不少于 64 时把链表转成红黑树，将最坏的 O(n) 拉回 O(log n)。这里 0.75 是"省空间"和"少撞车"之间的折中、不是最优解，一步到位的前提是哈希均匀、冲突少，最坏仍是 O(n)。所以"O(1) 总比 O(log n) 快"得改写：O(1) 说的是均摊或期望，跳表、平衡树的 O(log n) 反而更稳——常数、缓存命中、磁盘 I/O 这三件事，大 O 一概不知道。那个混血结构跳表出自 Pugh 1990 年（CACM 33(6): 668–676），查找平均 O(log n)，与红黑树同阶但期望常数不同，作者自述的卖点是实现简单、易于并发——有序集合选它是工程选择，不是理论必然。

## 有一类查找，任务是"确认它根本不在"

布隆过滤器花很少的内存位回答"这东西大概有没有见过"，论文出自 Bloom 1970 年、CACM 13(7): 422–426。它的脾气得两句话说完：会有假阳性、绝不会假阴性——判"一定没有"可靠，判"可能有"可能误报。Bloom 给的例子是每元素约 10 位、配 7 个哈希时假阳性约 1%，出自公式 (1 − e^(−kn/m))^k；这公式假设均匀独立，集合很小就会偏离。所以"不会漏"成立，"误判率就是 1%"则取决于位数与真实装载量。

日常落点是"为什么 App 一打开就认出你"：手机存着一段会话凭证（它不是密码，更像取物凭条）→ 请求带着它 → 服务端先翻近处的快速缓存，缓存外套一层布隆过滤器，把"这个键根本不存在"的查询挡在门外，重活才留给后端。这里串起来的是查找、缓存和哈希；凭条多安全是另一页的事，本页不担保"登录状态绝对安全"。

## 打错一个字还能被认出来，是因为在数改动次数

编辑距离（把 A 改成 B 最少要插入、删除、替换几次，Levenshtein 1966 年提出）本身就是一张动态规划表填出来的。"teh"改"the"距离是 1，用手就能验；但"recieve"改"receive"有两个答案：只许替换是 2 处，把相邻换位也算一次操作（变体叫 Damerau–Levenshtein）就是 1。不把"算的是哪一种"写在前面，"1 还是 2"就自相矛盾。数据库同理：一次节点访问能捎带几十到上百个键（这叫扇出），所以索引宁肯用 B+ 树，把随机访问压到 log_扇出(n)；而"二分 log₂n 次、B+ 树 log₁₀₀n 次"只是模型算式——要印"三层装多少亿条"，得先印扇出假设。
